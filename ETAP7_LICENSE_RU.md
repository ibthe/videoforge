# VideoForge — лицензирование с серверной одноразовой активацией

## Зафиксированные правила
- Пробный период: 7 дней с первого запуска приложения.
- Ваучер активации: создан для конкретного `installId` и email, действителен 7 дней с момента выпуска.
- После успешной активации сервер атомарно резервирует `licenseId` за первой установкой.
- Коммерческая лицензия действует 365 дней с момента первой активации.
- Повтор на той же установке возвращает прежний токен; другой `installId` получает отказ.
- Приложение содержит только открытый ключ сервера. Закрытые ключи отделены от исходников приложения.
- Сетевое время сверяется по HTTPS Date-заголовкам нескольких источников с обычной проверкой TLS-сертификатов. При офлайне используется локальное время с сохранённой максимальной отметкой; офлайн-режим слабее серверной проверки.

## Процесс выпуска
1. Клиент устанавливает VideoForge и открывает диалог лицензии. Там показан `ID установки`.
2. Клиент сообщает издателю email и ID установки.
3. Издатель выполняет команду из отдельного защищённого набора `VideoForge_license_issuer_private.zip`:

```bash
python -m pip install cryptography
python tools/issue_license.py --private-key /secure/issuer_private.pem --license-id VF-2026-0001 --email customer@example.com --install-id <ID_УСТАНОВКИ>
```

4. Выданный `VF1...` ваучер передаётся клиенту. Он должен активировать его в течение 7 дней.
5. Приложение отправляет ваучер, email и ID установки на сервер по HTTPS. Сервер проверяет подпись, срок, email и ID, а затем в одной транзакции SQLite закрепляет ключ и возвращает `VFL1...` — лицензию на год.

## Развёртывание сервера

Содержимое `licensing_server/` запускается за HTTPS reverse proxy. Для разработки:

```bash
cd licensing_server
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --host 127.0.0.1 --port 8000
```

По умолчанию сервер читает `keys/issuer_public.pem` и `keys/server_private.pem`. В production лучше монтировать ключи из secret manager/защищённого тома и использовать постоянное хранилище БД. Не выставляйте Uvicorn напрямую в интернет: нужен HTTPS с действительным сертификатом, rate limiting, резервное копирование базы, мониторинг и обновления зависимостей. При нескольких экземплярах сервера замените локальную SQLite на общую транзакционную БД.

## Настроить GitHub Actions

Добавьте в Settings → Secrets and variables → Actions → Variables переменную `LICENSE_SERVER_URL` со значением `https://ваш-домен/v1/activate`. Workflow передаёт её в сборки через `--dart-define`. Без переменной приложение соберётся, но онлайн-активация будет сообщать, что сервер не настроен.

## Безопасность и ограничения
- `installId` — случайный ID установки, не аппаратный отпечаток. Удаление данных приложения или переустановка может создать новый ID; серверная запись не даст перенести лицензию на новый ID автоматически. Предусмотрите ручной сброс/перенос лицензии через поддержку, если это требуется бизнес-правилами.
- Email подтверждается соответствием выданному ваучеру, но сам по себе не подтверждает владение почтовым ящиком. Если нужно подтверждение адреса, добавьте email verification в процесс продажи.
- Офлайн-издательский закрытый ключ и серверный закрытый ключ должны храниться раздельно. Никогда не включайте их в приложение или общий публичный репозиторий.
- В данном комплекте нет панели продаж, оплаты, самообслуживания переноса, отзыва лицензий или восстановления через email.
- HTTP `Date` заголовки не являются подписанным протоколом времени. Проверка нескольких TLS-источников — полезная эвристика, но не абсолютная гарантия при контроле устройства пользователем.

## Проверки
Проверены статическая структура и Python-синтаксис. Для полной проверки выполните тесты сервера и GitHub Actions для всех платформ. В окружении подготовки нет Flutter SDK, поэтому Flutter build/analyze не подтверждены.
