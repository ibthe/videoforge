# Этап 7 — лицензирование VideoForge

## Что добавлено
- 7-дневный пробный период с сохранением даты начала.
- Проверка сетевого времени через HTTPS `Date` заголовки `ya.ru`, `google.com`, `microsoft.com`, `cloudflare.com`, `apple.com`; используются системные TLS-проверки сертификатов `HttpClient`.
- Для принятия сетевого времени требуется минимум два доступных источника; применяется медианное значение.
- Если часы устройства отстают от сетевого времени более чем на час, сохранённый ключ удаляется и активация блокируется до проверки времени при нормальной разнице.
- Если часы спешат более чем на час, ключ не удаляется и блокировка не снимается.
- При отсутствии сети используется время устройства; отдельно запоминается максимальное наблюдавшееся время для обнаружения простого отката часов.
- Лицензионные токены подписываются Ed25519. В приложение встраивается только открытый ключ, закрытый ключ нужен только издателю лицензий.
- На данный момент проверка лицензии включена перед запуском основной очереди кодирования и созданием/сравнением тестовых клипов.

## Формат ключа
`VF1.<base64url(JSON payload)>.<base64url(Ed25519 signature)>`

Подписываемый JSON включает `licenseId`, `issuedAt`, `expiresAt` (Unix time в миллисекундах); необязательное поле `installId` привязывает лицензию к конкретной установке.

## Выпуск ключа
Нужен Python и пакет `cryptography`:

```bash
python -m pip install cryptography
python tools/issue_license.py --private-key /secure/private.pem --license-id VF-0001 --days 365
```

Для привязки к установке добавьте `--install-id <ID>`. ID установки следует показывать пользователю в интерфейсе перед коммерческим выпуском ключей; в текущем интерфейсе это пока не выведено, поэтому для первой версии выпускайте ключи без привязки к устройству.

**Безопасность:** закрытый ключ нельзя помещать в ZIP приложения, GitHub-репозиторий или клиентский код. Потеря/утечка закрытого ключа требует смены пары ключей и обновления встроенного открытого ключа.

## Ограничения первой версии
- Это локальная проверка; нет серверного отзыва лицензий, панели продаж, платежей или ограничения количества активаций.
- Заголовок HTTPS `Date` не является подписанным протоколом времени. Проверка нескольких независимых источников повышает устойчивость, но не заменяет доверенный time API.
- Офлайн-режим неизбежно слабее: часы устройства используются как запасной источник. `SharedPreferences` не является защищённым хранилищем от пользователя с root/jailbreak или от модификации приложения.
- При нормальном времени после предыдущей блокировки повторная активация разрешается, но истёкший токен не проходит проверку.

## Проверки
Архив и статическую структуру можно проверить локально. В окружении сборки не установлен Flutter SDK, поэтому `flutter analyze` и реальные сборки Android/iOS/macOS/Windows необходимо выполнить через GitHub Actions.
